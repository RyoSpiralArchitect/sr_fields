# Contributing

Keep changes focused on one layer where possible. Identify prompt changes by their instruction hashes and describe which evidence applies. Check app changes in the browser and test runtime changes against relevant failure, budget and record-handling cases.

Use only public or deliberately authored examples in issues, fixtures and pull requests. Do not attach private source YAML, credentials, run archives or personal conversations. New Field interpretations are proposals; do not silently merge similarly named concepts or invent source authority.

Run the commands in the README before proposing a change. For UI changes, exercise tabs, keyboard navigation, the selected scenario/case, prompt preview and mobile layout. A live API check is optional and separate from ordinary CI; the test suite must not require a key.

Preserve missing and negative outcomes. Record the exact instructions and hash for each condition. Do not replace historical results, treat an author annotation as independent ground truth, or claim semantic improvement from interface compliance alone.
