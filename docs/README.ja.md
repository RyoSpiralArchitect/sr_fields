# 名づける前の観測室

数値の揺らぎ、対話の経過、Fieldを使った返答を行き来する、小さな実験アプリです。

[English README](../README.md) · [3層の構成](architecture.md) · [プロンプトの追加](../prompts/README.md)

## 起動する

Python 3.10以降で、Repoのルートから実行します。追加パッケージは不要です。

```sh
python3 -I -S scripts/observatory.py serve
```

ブラウザで **http://127.0.0.1:8768** を開きます。初期画面は英語で、右上の「Interface language」から日本語に切り替えられます。最初は保存済みの記録とプロンプトを閲覧するモードです。終了は Ctrl-C。

- **数値の軌跡**：同じ信号を即時観測と履歴EMAで読み、保留幅を変えて比較。
- **言葉の経過**：12対話の各段階で、分類欄と実際の返答を読み比べる。
- **Fieldと返答**：旧版のAPI実験17応答と1欠測をそのまま確認。
- **プロンプトを組む**：12の方針を全部ON・単一・任意の組み合わせで選び、順序も変更。8つのプリセットと、通常文・名前付きJSON・共通指示のみを選べます。日英のsystem promptを表示・コピー・JSON保存できます。

問いのボタンは各画面の例を連動させます。数値の判断と人の言葉の意味を、同じ尺度で測ったことにはしません。

## 3層を育てる

| 層 | 置き場所 | 変更するもの |
| --- | --- | --- |
| アプリ | `app/` | 何を見比べ、どの段階を開き、どう操作するか |
| runtime | `runtime/field_observatory/` | プロンプトの組み立て、通信、実行上限、失敗と記録 |
| system prompt | `prompts/` | 意味論的な応答方針と組み合わせ |

非公開の元YAMLは配布物に含めません。公開する方針は、原典を手がかりに今回書き下ろした解釈です。原典の完全な定義や、未定義の式を実装したものではありません。原典との対応記録は公開Repoの外で管理します。

従来の7種に、HeartField・BodyField・ShieldField・RecursiveDrive・CollapseDriveを追加して12種にしました。依頼に応じて必要な方針だけを使い、明示された決定まで保留しない設計です。

## 言語と組み合わせを選ぶ

画面の言語とsystem promptの言語は独立しています。英語画面で日本語プロンプトも、日本語画面で英語プロンプトも使えます。各Fieldの説明は画面の言語、正確な送信文のプレビューはプロンプトの言語に従います。

最初は全部ONです。「これだけ」で一つに絞り、チェックで追加・解除し、矢印で順序を変更できます。選択・順序・形式・プロンプト言語は端末内に保存します。入力中の文章は言語切り替えでは保たれますが、再読み込み後には保存されません。空の選択では共通指示のみの形式を使います。

```sh
python3 -I -S scripts/observatory.py prompt --language ja --fields ShieldField HeartField
```

CLIも英語が初期値です。従来と同じ日本語版を使うときは `--language ja` を指定します。日英で意図を揃えていますが、効果の同等性は未検証です。過去の対話・返答は原文の日本語を保っています。[詳しい仕様](bilingual-composition.md)

## 最初の実験「名づける前の一言」

短い日本語の対話を、共通指示のみ・ThresholdFieldありの2条件で読み比べます。新しい試行の既定モデルは `gpt-6-sol` です。最初の実行では、どちらも感情を決めつけず、共通指示は「何が」、ThresholdFieldありは「どの瞬間が」と聞き返しました。次のコマンドで、実際に渡す2件の内容を手元で確認できます。[実験手順](../experimental/naming-hold/README.md) · [2件の返答と観察](../experimental/naming-hold/observations.md)

```sh
python3 -I -S experimental/naming-hold/run.py
```

英語の実験では、全4,096条件を各3つのseedで試し、12,288件すべての返答を得ました。他のFieldとseedを揃えてGentleFieldを足すと、この場面では疑問符を含む返答が64.0%から90.7%に増えました。[日本語の観察メモと実際の英文](../experimental/english-powerset/observations.ja.md) · [全12個の集計](../experimental/english-powerset/results/field-contrasts.csv)

続いて「恥ずかしかった」「うれしかった」の一語を変えた2条件を加え、さらに24,576件を比較しました。疑問符のある返答はそれぞれ82.83%と8.40%でした。2条件で逆向きに出たFieldの差と、本人が言っていない前提を調べた144件の読みを収録しています。[3条件の日本語レポート](../experimental/english-emotion-pair/observations.ja.md)

## 自分の言葉で1回試す

既存の安全な方法で、サーバーを起動する環境に `OPENAI_API_KEY` を渡したうえで実行します。アプリにキーを入力する欄はありません。

```sh
python3 -I -S scripts/observatory.py serve --enable-api --max-requests 3
```

「この入力で1回試す」を押すと、その入力と選んだ方針をOpenAIへ送信します。初期設定は600出力トークン・プロセスあたり3回まで。失敗・未完了・空の返答で停止し、自動で再送しません。

新しい記録は非公開用の `.runs/` に保存します。公開データへの自動追加は行いません。キーはサーバー内だけで扱い、ファイルへ保存しません。送信済みリクエストは、アプリを止めても相手側の処理まで取り消せるとは限りません。

## 記録の読み方

旧版の17応答は原文の引用を含む入力で得た結果です。公開プロンプトでの英語実験とは入力条件が違います。英語実験で測ったのは一つの対話での表現の変化です。話し手にとっての有用性は未評価です。

分類欄でBを選んだ返答でも、文章では「結果が出たら教えてください」と未確定性を保つ場合がありました。「分類を保留できたか」と「実際に意味を決めつけたか」を別々に読みます。

検証・配布方法は [English README](../README.md#check-and-package)、公開境界は [public-boundary.md](public-boundary.md) を参照してください。
